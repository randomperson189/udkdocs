개요

이 페이지는 머티리얼 에디터에서 사용가능한 모든 머티리얼 표현식 표현식에 대한 참고서입니다. 머티리얼 표현식이란 언리얼 엔진 3에서 제대로 돌아가는 머티리얼을 만들어 내는 데 사용되는 구성 블록같은 겁니다. 각 머티리얼 표현식은 하나 이상의 구체적인 값 세트를 출력하거나, 하나 이상의 입력값을 계산한 다음 결과를 출력하는 자체독립 블랙 박스입니다.

관련된 내용이 있을 수 있는 기타 페이지로는 머티리얼 튜토리얼 페이지가 있는데, 다양한 머티리얼 효과를 내기 위한 표현식 조합법에 대한 설명서입니다. 머티리얼 에디터 자체에 대한 사용법은, 머티리얼 에디터? 페이지를 참고하십시오. 프로그래머 용으로는 머티리얼 표현식 제작하기 페이지에서 머티리얼 표현식을 새로 만드는 법에 대한 자세한 내용을 참고해 보실 수 있습니다.

파라미터

어떤 머티리얼 표현식은 파라미터, 즉 그걸 포함하는 베이스 머티리얼의 머티리얼 인스턴스 내에서 (어떤 경우에는 실행시간 도중에 동적으로) 그 값을 변경할 수 있음을 뜻합니다. 이런 표현식을 머티리얼 인스턴스의 특정 파라미터를 식별하는 데 사용하기 위해서는, Parameter Name (파라미터 이름) 속성을 통해 고유한 이름을 줘야 합니다. 같은 종류의 파라미터 둘이 같은 머티리얼 안에 이름까지 같다면, 같은 파라미터로 간주됩니다. 머티리얼 인스턴스의 파라미터 값을 바꾸면, 머티리얼에 있는 두 파라미터 표현식의 값 모두 바뀌게 됩니다. 파라미터의 디폴트값도 베이스 머티리얼에 설정되어 있습니다. 머티리얼 인스턴스에서 따로 덮어써서 변경하지 않으면, 거기서도 파라미터의 디폴트값이 됩니다.

상세 정보는 Instanced Materials KR, Material Instance Constant KR 페이지를 참고하십시오.

머티리얼 제작시의 색 고려 방법

UE3에서 머티리얼에 대해 고려할 때, 많은 표현식이 각 채널에 독립적으로 작동함에 유의하십시오. 예를 들어 Add 표현식은 입력을 둘 받아 채널별로 더합니다. (3채널 값인) RGB 색 둘을 더하면, 출력 색은 (빨강1+빨강2, 초록1+초록2, 파랑1+파랑2)가 됩니다. 채널별 연산은 그레이스케일 값에 대한 연산으로 간주하십시오.

채널별 연산을 수행하는 표현식은 일반적으로 채널 수가 같은 입력을 필요로 합니다. 예로 RGB 색을 다른 RGB 색에다 더할 수는 있지만, 알파 채널이 없는 RGB 색에다 RGBA 색을 더할 수는 없습니다. 이 규칙의 예외는 입력 중 하나가 단일 채널(그레이스케일) 값일 때인데, 아무데나 더할 수 있기 때문입니다. 즉 RGB 색 (0.2,0.3,0.5)에다 0.1을 더하면 (0.3,0.4,0.6)이 됩니다.

다른 주의사항으로는 언리얼 엔진의 색은 부동 소수점 이라는 겁니다. 다른 말로, [0,255] 사이의 RGB 값이 아니란 소립니다. 대신 RGB 값은 어느 것이나 가능합니다. 0.4, -1.2, 3.4 와 같은 식이 가능한 것이며, 0.0은 검정/무색(구형 스키마에서의 0)이며, 1.0은 풀 컬러(구형 스키마에서의 255)라는 뜻입니다. 그렇긴 해도, 1.0 이상의 값도 완전 가능합니다. 클 수록 밝은거죠! 빨강은 (255,0,0)이었으나, 언리얼 엔진에서의 빨강은 (1.0,0.0,0.0)이며, 정말 밝은 빨강은 (3.0,0.0,0.0) 입니다.

색은 음수도 가능합니다! 음수 색은 색을 지우는 걸로 생각하면 됩니다. 예를 들어 텍스처에 (-0.5,0.0,0.0)을 더하면 텍스처에 있는 빨강색을 0.5만큼 줄인다는 소리입니다.

중간 표현식은 부동 소수점으로 계산되지만, 머티리얼 최종 출력 색의 각 채널은 [0,1] 범위로 좁혀지게 되며, 0은 무기여, 1은 전체 기여를 뜻합니다. 1 이상의 값은 색이야 같지만 블룸 밝기 패스에 뽑힌 다음, 채널의 크기가 직접 블룸 공헌에 영향을 끼치게 됩니다.

머티리얼 표현식

  1. 설명, 주석 - 모든 머티리얼 표현식에는 공용 속성 Desc (설명)이 있습니다. 이 속성에 입력된 문구가 머티리얼 에디터에서 표현식 바로 위 작업공간에 표시됩니다. 어떤 식으로 사용해도 괜찮지만, 보통은 표현식의 용도나 기능에 대해 짧막히 적어두기에 좋습니다.
  2. 제목 바 - 머티리얼 표현식의 속성에 관한 적절한 정보나 이름이 표시됩니다.
  3. 출력 - 머티리얼 표현식 연산의 결과물이 출력되는 링크입니다.
  4. 미리보기 - 머티리얼 표현식의 출력값을 미리보여주는 창입니다. 실시간 업데이트 모드를 켜면 자동으로 업데이트됩니다. 스페이스바를 쳐서 수동으로 업데이트시킬 수도 있습니다.
  5. 입력 - 머티리얼 표현식이 사용할 값을 받아들이는 링크입니다.

Abs

Abs는 수학 용어 "absolute value"(절대값)의 약자입니다. Abs 표현식은 받아들인 입력값의 절대값, 또는 부호를 뺀 값을 출력합니다. 근본적으로 음수는 - 부호를 버려 양수로 만들고, 양수랑 0은 그대로 놔둔다는 뜻입니다.

예제: -0.7 Abs는 0.7; -1.0 Abs는 1.0; 1.0 Abs 역시 1.0

용례: Abs는 보통 DotProduct 와 함께 사용됩니다. DotProduct(도트 곱)은 -1..0..1 값을 지니는 반면, 도트 곱의 절대값은 1..0..1 값이 됩니다.

Add

(더하기) 포토샵의 화면 레이어 블렌드와 유사하게, Add 표현식은 두 입력을 받아서 더한 다음 결과를 출력합니다. 덧셈은 채널별로 이루어 집니다. meaning that the inputs' R channels get added, G channels get added, B channels get added, etc. Both inputs must have the same number of channels unless one of them is a single Constant value. Constants can be added to a vector with any number of inputs.

입력

  • A - 여기다가 더합니다.
  • B - 더해질 값입니다.

예제: 0.2 와 0.4 Add 는 0.6; (0.2,-0.4,0.6) 와 (0.1,0.5,1.0) Add 는 (0.3,0.1,1.6); (0.2,-0.4,0.6) 와 1.0 Add 는 (1.2,0.6,1.6)

용례: Add 는 보통 색을 밝고/어둡게 하거나 UV를 오프셋시킬 때 씁니다.

AntialiasedTextureMask

(앤티앨리어싱된 텍스처 마스크) 부드러운 (앤티-앨리어싱된) 전이 마스크를 사용하여 머티리얼을 만들 수 있는 머티리얼 표현식입니다. 이 마스크는 복잡한 머티리얼 속성 둘을 블렌딩하거나 (SoftMasked와 궁합이 잘 맞는) 알파 블렌딩된 머티리얼을 페이드 아웃시키는 데 쓸 수 있습니다. 그냥 한 (빨강, 초록, 파랑, 알파) 채널에 마스크가 할당된 텍스처를 지정하고, 표현식에 사용된 채널을 설정한 뒤 비교값을 지정합니다. 채널이 0=검정에서 1=하양까지의 그레이스케일 값을 갖는다 가정하고, 비교 함수가 결과 마스크를 0과 1로 정의합니다. 이 표현식은 파리미터이며, 자식 머티리얼 인스턴스에서 Texture (텍스처) 속성을 덮어쓸 수 있습니다.

프로퍼티

  • Threshold (한계점) - 픽셀 범위의 한계점으로 사용되는 값입니다. 이 값보다 픽셀 범위가 작으면 검정이, 크면 하양이 됩니다.
  • Channel (채널) - 마스크로 사용할 텍스처의 채널을 지정합니다.
  • Texture (텍스처) - 사용할 마스크 텍스처를 지정합니다.

입력

  • UVs - 텍스처 마스크에 적용할 텍스처 좌표를 받습니다.

의사 코드(Pseudo code)는: 

Result = 1
if TextureLookup < Threshold then Result = 0

실제 구현은 약간 더 복잡한데, 앨리어싱을 피하기 위해 실제 픽셀 범위에 따라 0과 1 사이의 값을 반환하려 하기 때문입니다.

예제(최상의 품질을 위해 미압축 상태인 자그마한 128x128 텍스처):

구현 세부사항은 앤티앨리어싱으로 알파 테스트 개선하기 페이지를 참고하십시오.

AppendVector

(벡터 덧붙임) 세 가지 그레이스케일로 된 풀 컬러 RGB 이미지와 마찬가지로, AppendVector로는 채널을 결합하여 원래보다 많은 채널을 가진 벡터를 만들 수 있습니다. 예를 들어 두 개의 수 (Constant) 를 덧붙여 2채널 값 (Constant2Vector) 생성이 가능합니다.

입력

  • A - 여기다가 덧붙입니다.
  • B - 덧붙일 값입니다.

예제: 0.2 와 0.4 Append 는 (0.2,0.4); (0.2,0.4) 와 (1.6) Append 는 (0.2,0.4,1.6).

BumpOffset

BumpOffset(돌기, 범프오프셋)이란 언리얼 엔진 3 용어로 일반적으로는 'parallax mapping', 관측시차 매핑을 뜻합니다. BumpOffset 머티리얼은 별도로 지오메트리를 추가할 필요 없이 입체감을 냅니다. BumpOffset 머티리얼은 심도 정보를 주기 위해 heightmap(하이트맵)을 이용합니다. 하이트맵의 값이 밝을 수록, 머티리얼도 '튀어 나와' 보이게 되며, 카메라가 표면을 따라 움직이면서 이와 같은 구역에는 관측시차가 (움직여) 보이게 됩니다. 하이트맵에서 어두운 구역은 '멀리 있는' 곳으로, 가장 조금 움직이게 됩니다.

프로퍼티

  • HeightRatio: (높이비율) 하이트맵 에서 취한 심도에 대한 곱수입니다. 값이 클수록 깊이도 심해집니다. 전형적인 값은 .02에서 .1 사이입니다.
  • ReferencePlane: (참조평면) 효과를 적용할 텍스처 평면에서의 대략 높이를 지정합니다. 값이 0 이면 텍스처가 표면에서 완전히 떨어져 보이며, (디폴트값) 0.5 면 표면 일부는 튀어나오고 일부는 가라앉아 보이게 됩니다.

입력

  • Coordinate (좌표) - 표현식이 변경 기준으로 삼을 텍스처 좌표입니다.
  • Height (높이) - 하이트맵으로 사용할 텍스처(나 값)입니다.

CameraVector

(카메라 벡터) 표면에 대한 카메라의 방향을 나타내는 3채널 값입니다.

용례: CameraVector는 보통 CameraVector를 ComponentMask에 연결하고 CameraVector의 X와 Y채널을 텍스처 좌표로 사용하여 환경 맵(environment map)을 속이는 데 사용됩니다.

(커서를 올리면 그림이 움직입니다.)

CameraWorldPosition

(카메라 월드 포지션) 월드 공간에서의 카메라 위치입니다.

카메라가 회전하면서 미리보기 구체 색이 변합니다.

Ceil

(천정) 소수점을 무조건 올려 다음 정수로 만듭니다. Floor 및 Frac 도 참고해 보십시오.

예제: 0.2 의 Ceil 은 1.0; (0.2,1.6) 의 Ceil 은 (1.0,2.0).

Clamp

(제한) 최소(Min)와 최대(Max)값으로 정의된 특정 범위내에 값을 제한시키는 데 사용됩니다. "Min 0.0, Max 0.5" 는 결과값이 0.0보다 작거나 0.5보다 클 수 없다는 뜻입니다.

입력

  • Min (최소) - 제한시킬 최소값입니다.
  • Max (최대) - 제한시킬 최대값입니다.

예제: 0.3 을 Min 0.0 과 Max 1.0 으로 Clamp 하면 0.3; 1.3 을 Min 0.0 과 Max 1.0 으로 Clamp 하면 1.0;

   MaxZ = 16777215

(버텍스 컬러) 스프라이트 파티클 이미터에 영향을 끼치는 컬러 모듈의 출력으로의 머티리얼용 액세스 포인트가 되는 표현식입니다.

출력

  • RGB - 색의 3채널 RGB 벡터값을 출력합니다.
  • R - 색의 빨강 채널을 출력합니다.
  • G - 색의 초록 채널을 출력합니다.
  • B - 색의 파랑 채널을 출력합니다.
  • A - 색의 알파 채널을 출력합니다.

경고: VertexColor는 제한된 보간자로 인해 Transform과 상호 배제 관계에 있습니다. Transform과 VertexColor 표현식을 둘 다 사용하면, VertexColor는 전부 하얗게 나오게 됩니다.

프로그래머용: 메시 파티클에 대한 색은 셰이더 상수로 설정되는 반면, 스프라이트 파티클에 대한 색은 버텍스별 셰이더와 소통합니다.

WindDirectionAndSpeed

4채널 벡터값으로 바람 방향(RGB 채널 크기에 따라 풍력)과 바람 속도(A 채널)를 출력하는 표현식입니다. 각각의 값은 각 오브젝트에 영향을 끼치는 바람 액터로부터 파생됩니다.

이 표현식은 바람 액터에 영향을 끼치는(WindDirectionalSource 또는 WindPointSource의) 것에 따라 코드 베이스로 설정됩니다. 영향을 끼치는 바람 액터가 여럿인 경우, 그 특성치(attribute)가 가중치(weight)에 따라 서로 섞이게 됩니다. WindPointSource의 것에 대해 이게 뜻하는 바는, 이 표현식을 포함한 머티리얼을 사용하는 오브젝트가 그 진원지에 가까울수록, WindDirectionAndSpeed에 대한 진원지의 영향력도 세 진다는 뜻입니다. WorldPositionOffset 과 함께 사용하면 바람 애니메이션을 싸게 만들수 있는 표현식입니다.
